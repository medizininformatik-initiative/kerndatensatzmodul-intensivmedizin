## Changes in 2027.0.0

First formal publication of this module through the HL7 IG Publisher, based on the MII KDS module template. This section lists all changes since 2026.0.x, including those of the 2027.0.0-ballot releases; each entry links the pull requests behind it.

- **`BREAKING`** Require category[vs-cat].coding 1..1 in the generic monitoring/vital-data profile, inherited by birth weight, birth length, recumbent body length, indirect-calorimetry energy expenditure and carbon dioxide production. Remove the redundant local body-length rule. The required vital-signs code remains unchanged; additional categories remain allowed, but additional codings inside the vital-signs slice are no longer permitted. ([NRA-1190](https://imi-uka.atlassian.net/browse/NRA-1190); PR [#205](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/205)).
- **`BREAKING`** In the draft recumbent-body-length profile, replace mandatory IEEE 11073 68060 with 188740 (MDC_LEN_BODY_ACTUAL). The lying position remains specified by LOINC 8306-3 and SNOMED CT 1149101003; IEEE 188740 alone does not specify posture. Explicitly require category[vs-cat].coding 1..1. Retain validator-required LOINC 8302-2, canonical URL and parent. Update the example and regression tests. ([NRA-1190](https://imi-uka.atlassian.net/browse/NRA-1190); PR [#205](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/205)).
- **`BREAKING`** Correct *Airway pressure at zero inspiratory flow* to match LOINC 20060-0. Profile id/name and canonical change from `mii-pr-icu-vent-atemwegsdruck-bei-null-expiratorischem-gasfluss` to `mii-pr-icu-vent-atemwegsdruck-bei-null-inspiratorischem-gasfluss`; the new canonical is `https://www.medizininformatik-initiative.de/fhir/ext/modul-icu/StructureDefinition/mii-pr-icu-vent-atemwegsdruck-bei-null-inspiratorischem-gasfluss`. Update `meta.profile`, dependent `baseDefinition` references and interface configurations. The 2026.0.2 package used `https://www.medizininformatik-initiative.de/fhir/ext/modul-icu/StructureDefinition/mii-pr-icu-atemwegsdruck-bei-null-expiratorischem-gasfluss`; that identifier is also historical. LOINC 20060-0, the artificial-ventilation category, cm[H2O], active status and parent are retained. Measurement coding version is required without fixing an edition or display. Examples and translations use the corrected terminology. Addresses [#201, point 1](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/issues/201). Only the single LOINC measurement coding is permitted; additional measurement codings are rejected.
- **`BREAKING`** Migration to the MII KDS module template: the guide is now published on GitHub Pages (this site) instead of Simplifier; page locations changed (see the navigation), the ImplementationGuide id is now `mii-ig-icu` (PR [#74](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/74))
- **`BREAKING`** **Canonical URLs changed for 27 profiles now maintained in ISiK 6.** The balance profiles (generic *Bilanz* and its 19 specialisations), the six examination profiles (pupils) and the *RASS* score moved to the ISiK 6 package (`de.gematik.isik` 6.0.0) and were removed from this module, together with their 11 value sets. The profile ids stay the same, but the canonical changes from `https://www.medizininformatik-initiative.de/fhir/ext/modul-icu/StructureDefinition/<id>` to `https://gematik.de/fhir/isik/StructureDefinition/<id>`. **Instances and dependent profiles that reference the MII canonicals must switch to the ISiK canonicals** (`meta.profile`, `baseDefinition`). The MII value sets `mii-vs-icu-*` for balances, pupils, RASS and millilitre units are replaced by the ISiK copies. The guide renders the ISiK versions on its own pages (`extern-<id>.html`), and the examples declare the ISiK canonicals. *Bilanz Einfuhr Kalorien 24h* stays in this module and now derives directly from `Observation`, so it no longer inherits fluid-balance codes or millilitre units. The ventilation profiles are unchanged. (PRs [#144](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/144), [#146](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/146))
- **`BREAKING`** QI7 body measurements: *Körpergewicht* and *Körpergröße* restrict `value[x]` to `Quantity`, close the measurement coding slices and require the measurement-specific IEEE 11073 coding in addition to LOINC and SNOMED CT. Birth-specific and recumbent-length codings are excluded from general weight and height as applicable; use the dedicated profiles for these measurements. The measurement codings in the profiles revised by QI7 require `Coding.version 1..1 MS`, without fixing an edition or display. Existing instances with other value types, missing required codings or versions, or additional measurement codings must be adapted. (PR [#155](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/155))
- **`BREAKING`** *Körperlänge* changes from `active` to `draft` and derives from the new draft monitoring base. Its CapabilityStatement support changes from SHALL to MAY. Release builds remove this profile and its example together with the other drafts; it remains available in development previews that include drafts. Its LOINC 8306-3 coding is supplemented by mandatory LOINC 8302-2 for compatibility with the current HL7 Java validator. (PR [#155](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/155))
- QI7 adds draft profiles for *Geburtsgewicht* (grams only), *Körperlänge bei Geburt* (centimetres), body-weight-normalised *Energieverbrauch Indirekte Kalorimetrie* (`kcal/kg/d`) and *Kalorienbedarf pro Tag*. The birth-measurement profiles derive from the independent MII monitoring base and exclude the general body-weight/body-height LOINC codes. The calorie-requirement profile derives directly from `Observation`; its extensible method value set distinguishes calculated and estimated requirements. These new draft profiles are excluded from release builds. (PR [#155](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/155))
- **`BREAKING`** *Bilanz Einfuhr Kalorien 24h* now permits only its specified LOINC and SNOMED CT measurement codings and requires their versions. Instances carrying inherited fluid-balance codings must be updated. The profile remains a draft. (PR [#155](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/155))
- Dependencies raised to the 2027 generation (`kerndatensatz.base`, `kerndatensatz.meta` 2027.0.0-ballot) and ISiK 6.0.0 (PRs [#74](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/74), [#96](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/96))

They are now `component-interpretation` and `component-referencerange`; the canonical URLs of both SearchParameters are unchanged (PR [#149](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/149))
- `fix` SOFA score: the six subscore components no longer carry SNOMED CT placeholder codings (`xxx`/`xxxx`), since SNOMED CT has no concepts for the SOFA subscores. Each component is now identified by its LOINC code alone (`code.coding` 1..1) (PR [#156](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/156))
- **`BREAKING`** CAM-ICU score (draft): the score now records only the overall result (positive or negative) and is identified by the DGAI code `DGAI-CAM-ICU`; the four feature components were removed. The invalid codes LOINC `99844-5` and SNOMED CT `450740000` are no longer used; neither code system has a CAM-ICU-specific concept yet. A `dataAbsentReason` may be given instead of a result ([NRA-583](https://imi-uka.atlassian.net/browse/NRA-583); PRs [#157](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/157), [#173](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/173))

- New profile *MII PR ICU Score BPS* (draft): total score of the Behavioral Pain Scale (3 to 12) for mechanically ventilated adults, identified by the DGAI code `DGAI-BPS` (PR [#173](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/pull/173))

### Known issues

- The QA report still lists a substantial number of errors. **All of them are triaged and none is a content defect of this module** — the dominant causes are an IG-Publisher bug in batch terminology validation (upstream fix pending: [org.hl7.fhir.core#2460](https://github.com/hapifhir/org.hl7.fhir.core/pull/2460)), display texts pinned in profile patterns that differ from the official terminology displays ([#79](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/issues/79)), and terminology-server semantics for version-stamped SNOMED CT codings ([#83](https://github.com/medizininformatik-initiative/kerndatensatzmodul-intensivmedizin/issues/83)). Full breakdown: *Examples* page, section "Known validation issues".
- Two profile design conflicts are under discussion: the respiratory-rate/ECT-pressure category bindings versus the inherited FHIR core `vital-signs` requirement, and the body-site temperature codes versus `ISiKKernTempSctVS` (ISiK 6.0.0).
- `full-ig.zip` is not offered on the Downloads page — the archive exceeds GitHub's 100 MB file limit.
- The package has not been published to Simplifier yet; use the `package.tgz` of this publication in the meantime.
